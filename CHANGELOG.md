# Changelog

All notable changes to this project are recorded here.

## 1.1.0 - 2026-09-25

### Security

- Fragmented verification no longer reports supplied segments as valid when no binding in the active manifest covers them. C2PA 2.4 session-key and per-segment live streams have no fragment Merkle tree, so their segments were ignored and a tampered segment verified with `integrity: valid` and `hard_binding: match`. Such input now reports `livevideo.segment.invalid`, `integrity: invalid`, and `hard_binding: mismatch`.
- A claim signature whose COSE `payload` is not nil, including an empty byte string, is rejected with `claimSignature.mismatch`. C2PA signs claims in detached mode, and the verifier had been substituting the claim bytes for whatever the signature carried.
- A leaf certificate whose only extended key usage is time-stamping or OCSP signing no longer validates as a claim signer; it reports `signingCredential.invalid`.
- CAWG identity claims aggregation credentials are trusted only when the issuer DID is configured with `cawg_ica_trusted_issuers` or reaches one in `cawg_ica_trust_anchors`. Revocation entries are checked against `cawg_ica_status_lists`; a missing list is `cawg.ica.revocation.unavailable`, not a pass.
- An identity claims aggregation credential time-stamp is verified only against configured TSA trust. It no longer trusts the certificates the token carries.
- C2PA 2.4 forbids SHA-1 for content hashing ("The deprecated list is empty"). SHA-1 had been accepted for hashed-URI references under strict conformance and for general-box and collection hashes in both postures; it is now `algorithm.unsupported` everywhere, and the `sha1` dependency is gone.
- A data-hash exclusion covering the manifest store could also hide asset bytes, which then went unhashed. Every byte of such a range outside the store must be zeroed padding, and for JPEG the excluded length must equal the total length of the C2PA APP11 segments; otherwise `assertion.dataHash.mismatch`.
- A general box hash on GIF, RIFF, or Ogg was never evaluated, so a tampered box-hash-signed file read as valid. Those formats are now segmented per C2PA 2.4, and a box hash on a container with no box convention fails closed.
- BMFF files were read from the first C2PA box, so an appended `update` store was ignored and the original manifest validated in its place. The active store is now chosen by `box_purpose`.
- An update manifest carrying a second, non-parent ingredient passed. C2PA 2.4 allows exactly one ingredient, and it must be parentOf; anything else is `manifest.update.wrongParents`.
- Action and declaration rules the Validation chapter addresses to validators now apply by default for v2 claims: `c2pa.created` and `c2pa.opened` must open the first actions assertion and appear in exactly one; `c2pa.watermarked` and `c2pa.watermarked.bound` need a `c2pa.soft-binding` assertion (`assertion.action.softBindingMissing`); an assertion reachable only through the claim-generator icon is `assertion.undeclared`; and known assertions carried as JSON get the same semantic checks as CBOR.
- Fragments presented out of their signed order, or with a gap inside the supplied run, are `assertion.bmffHash.mismatch`, as C2PA 2.4 VAL-CONT-0007/0008 require, unless the caller signals the seek.
- Hashed URIs inside assertions (ingredient thumbnails and data, action ingredient and related-assertion references, software agent and template icons) were not checked, so a retargeted thumbnail reference still read as valid. They are now resolved and hashed: `hashedURI.missing` or `hashedURI.mismatch`. The assertion `metadata` subtree stays unvalidated, as C2PA 2.4 requires.
- Redaction declarations are checked: a claim may not redact its own assertion (`assertion.selfRedacted`), an actions assertion (`assertion.action.redacted`), or a hard binding (`assertion.hardBinding.redacted`), and an assertion declared redacted but still present is `assertion.notRedacted`. Only a lawful redaction lets an ingredient be authenticated through its claim signature.
- The TLS stack used by online checks, telemetry, and the update check moves to rustls 0.23.45, which fixes RUSTSEC-2026-0285 (TLS 1.3 handshake messages accepted across encryption levels).

### Added

- Live-stream verification for C2PA 2.4 fMP4 and CMAF streams, both `verifiable-segment-info` (session keys) and `per-segment` (chained manifests): Rust `verify_stream` and `verify_stream_with_options`, CLI `verify --encapsulation fmp4|cmaf --segment-mode ...`, Python `verify_stream`, WebAssembly `verifyStream`, C `encypher_c2pa_verify_stream`, and Go `VerifyStream`. Go also gains `VerifyFragmented`.
- `strict_conformance` on the CLI (`--strict-conformance`), Python, and Go. WebAssembly and C already accepted it in the options object.
- `trust_anchor_not_before` and `trust_anchor_not_after` bound caller-supplied anchors (C2PA 2.4 VAL-CRYP-0010/0011). Each anchor now carries one purpose, so a timestamp-authority anchor cannot validate a claim signer.
- CAWG identity claims aggregation options `cawg_ica_trusted_issuers`, `cawg_ica_trust_anchors`, and `cawg_ica_status_lists`, on every surface.
- Update manifests (`c2um`), including their inherited hard binding through an authenticated parent chain, `manifest.update.invalid`, and `manifest.update.wrongParents`.
- Brotli-compressed manifest stores (`brob`), expanded under a size bound, with `manifest.compressed.invalid` on failure. Compressed stores written by c2pa-rs verify at C2PA 2.2 and 2.4.
- PDF incremental history: each manifest store is validated against the file as it stood when its update section was written, reported under `manifest_report.pdf_incremental_history`.
- Registered status codes for checks that were missing or folded into others: `algorithm.unsupported` for an unsupported claim-signature algorithm, `timeStamp.mismatch`, `timeStamp.credentialInvalid`, `timeOfSigning.insideValidity` and `.outsideValidity`, `assertion.timestamp.malformed`, `assertion.outsideManifest` and `assertion.missing` in place of a single missing-reference code, `assertion.json.invalid`, `assertion.ingredient.malformed`, `assertion.action.ingredientMismatch`, `assertion.action.redactionMismatch`, `assertion.bmffHash.additionalExclusionsPresent`, `assertion.boxesHash.additionalExclusionsPresent`, `manifest.multipleParents`, `manifest.text.corruptedWrapper`, `manifest.text.multipleWrappers`, and the `manifest.structuredText.*` codes.
- Extension codes under `com.encypher.*` for outcomes the registries do not name. [Report schema](docs/REPORT_SCHEMA.md) lists them.
- `expected_seek_positions` (`--expected-seek`, Python `expected_seek_positions`, Go `ExpectedSeekPositions`) lets a player mark intentional seeks in fragmented and stream verification.
- PDF discovery through cross-reference streams, the C2PA font table record (a remote-only table reports `manifest.inaccessible`), and the C2PA 2.4 unstructured-text hash (wrapper removed, remainder NFC-normalized).
- `verify_with_manifest_store` verifies an asset against a C2PA Manifest Store held outside it, such as a `.c2pa` sidecar or a store the caller fetched from the URI the asset declares. CLI `verify --manifest FILE`, Python `verify(manifest_store=...)`, Go `VerifyWithManifestStore`, WebAssembly `verifyWithManifestStore`, C `encypher_c2pa_verify_with_manifest_store`. Nothing is fetched unless online checks are allowed.
- Remote-manifest discovery: an asset with no embedded manifest whose XMP `dcterms:provenance` names one reports `manifest.inaccessible` with `details.remote_manifest_uri`. XMP is read from each format's standard location.
- Offline validation of `c2pa.cloud-data` and external-reference assertions with their registered codes. Content that would need fetching is `assertion.inaccessible`, which C2PA 2.4 says shall not reject a claim.
- Recursive ingredient validation, bounded at 16 edges and 64 manifests and cycle-safe. Each ingredient manifest's claim, claim signature, and bindings are checked, and the outcome is reported as `validation_results.ingredientDeltas` and in crJSON. Ingredient defects never change the active verdict. `ingredient.unknownProvenance` marks an ingredient with no manifest link.
- CAWG metadata 1.1 and training-and-mining 1.1 validation. Malformed assertions report `com.encypher.cawg.metadata.invalid` or `com.encypher.cawg.trainingMining.invalid`, and the effective permission for each training and mining use is reported under `com.encypher.cawg.trainingMining.effectiveUse` (a `constrained` entry without constraint information reads as `notAllowed`). Neither spec registers status codes.
- `scripts/refresh-trust-snapshot` regenerates the packaged trust snapshot, and a weekly CI job reports drift from the upstream lists. Encypher targets a refresh release within 30 days of an upstream change.
- Caller-supplied online evidence on `VerifyOptions`: `ocsp_responses`, `ocsp_unreachable`, and `external_data` accept material an offline run could not reach. OCSP responses are evaluated under the C2PA 2.4 and CAWG 1.3 online rules and replace `signingCredential.ocsp.skipped` or `cawg.x509.ocsp.skipped` with a real verdict; a responder the caller tried and could not reach reports `signingCredential.ocsp.inaccessible` or `cawg.x509.ocsp.inaccessible`. External content is hashed against the assertion's own `alg` and `hash` before anything else is done with it. The verification kernel still opens no socket.
- Online checks, off by default. When a file points at something only the network can settle (a remote manifest, the signer's or a CAWG identity's OCSP responder, a `did:web` issuer, cloud-data content), the command line asks before contacting anyone: yes this time, no, always, or never. `always` and `never` are saved in `online.json`; `--online` and `--offline` decide one run; `encypher-c2pa online on|off|ask|status` manages the saved choice; `ENCYPHER_C2PA_ONLINE` overrides everything. Libraries never ask and never read the saved choice: they fetch only with `online: true` or the environment variable, because they may be verifying untrusted files on a server. Fetches reach public addresses only, with size, time, redirect, and request limits, and never carry the file. The report gains a `network` block listing what could be checked, what was requested, and the outcome; revocation settled online reports `revocation.source: "online_ocsp"`. WebAssembly gains `verifyOnline`, which uses the browser's `fetch`.
- Update check for the command line, on by default. Once a day, when a person is at the terminal, the CLI reads its crates.io index entry and offers a newer release: `[y] yes  [N] not now  [s] skip this version  [o] stop checking`. `y` installs with `cargo install --locked` and re-runs the command on the new version, so users pick up verification fixes and refreshed trust lists. Runs without a terminal and runs with `--offline` never check; libraries never check. `encypher-c2pa update` checks and installs now; `encypher-c2pa update-check on|off|status`, `{"check": false}` in `update.json`, or `ENCYPHER_C2PA_UPDATE_CHECK` control it.
- `config_directory()` returns the directory holding saved preferences.

### Changed

- The CAWG trust configuration is evaluated per source, as CAWG Identity 1.3 defines it. The interim S/MIME conditions now bind only the two sources that section names, the Mozilla email root store and the IPTC Verified News Publishers lists. An identity that chains to the packaged Encypher Verified Organizations root, or to anchors supplied in `cawg_trust_pem` or `cawg_allowed_certs_pem`, is accepted under the base trust model, so it reads `cawg.identity.trusted` without a time stamp and after 31 March 2027. It still needs `emailProtection` or `id-kp-documentSigning`, one of the six approved CA/Browser Forum S/MIME certificate policies, a valid chain to a configured CAWG anchor, and clean revocation evidence. The `trust_source` detail names the entry that accepted the credential: `encypher_verified_organizations`, `caller_supplied`, `smime_interim`, `allowed_list`, or `document_signing`.
- The interim S/MIME time condition is read as the disjunction CAWG Identity 1.3 states: a validation time on or before 31 March 2027, or a trusted time stamp establishing that the identity assertion was issued by then. An untimestamped S/MIME identity validated before the cutoff was previously rejected with `cawg.x509.credential.untrusted`; it is now accepted, and a time stamp is required only past the cutoff.
- CAWG statuses report the identity assertion's label as their `url`, such as `cawg.identity` or `cawg.identity__1`, which CAWG Identity 1.3 requires. They previously carried the assertion's JUMBF URI. C2PA statuses are unchanged.
- A referenced assertion in `signer_payload` and the matching claim reference resolve their hash algorithm against the claim before they are compared, as the C2PA hashed-URI definition requires. A reference that stated `alg` explicitly no longer mismatches a claim reference that inherits the same algorithm, which had produced a spurious `cawg.identity.assertion.mismatch`.
- A legacy v1 `sigTst` header on an identity claims aggregation credential is ignored rather than reported as `cawg.ica.time_stamp.invalid`, which is what CAWG Identity 1.3 tells a validator to do. The failure code now belongs to a `sigTst2` the validator could not verify.
- Certificates on a signing, time-stamp, or CAWG path are checked against the C2PA certificate profile and a backtracking RFC 5280 path search with basic, name, and policy constraints. A violation reports `signingCredential.invalid`, `timeStamp.credentialInvalid`, or `cawg.x509.credential.untrusted`. Policy mapping is not implemented and fails closed.
- A trusted legacy `sigTst` time-stamp now establishes signing time, as C2PA 2.4 VAL-CRYP-0028 requires; the verifier previously checked the token and discarded the result. Because a v1 imprint does not cover the signature value, the report adds `com.encypher.timestamp.v1SignatureUnbound`. Assets signed by since-expired certificates with a v1 time-stamp can now read as valid.
- The C2PA 2.4 action-ingredient rules are enforced: `c2pa.opened` needs exactly one parentOf ingredient, `c2pa.placed` componentOf ingredients in the same manifest, `c2pa.removed` componentOf ingredients in another manifest, and `c2pa.transcoded` or `c2pa.repackaged` parentOf ingredients when they name any. Claims written under C2PA 1.x are held to these rules only under strict conformance.
- Data-hash and box-hash exclusions are checked for order, overlap, bounds, and `boxIndex`. The box-hash algorithm falls back from the box entry to the box map to the claim.
- An omitted fragment Merkle tree is reported as not evaluated (`com.encypher.bmffHash.fragmentsNotEvaluated`) instead of as a successful match.
- Malformed asset structure (mislabeled boxes, a missing assertion store, duplicate labels, broken framing, an unreadable text carrier) is reported in the verification report instead of raised as an API error.
- A `claim_generator_info.specVersion` that is not SemVer is informational (`com.encypher.claim.specVersionNotSemver`) by default and `claim.malformed` under strict conformance.
- Strict mode: the Conformance Program's trusted-timestamp and revocation requirements report `com.encypher.conformance.trustedTimeStampMissing` and `com.encypher.conformance.revocationInformationMissing`. They replace `timeStamp.missing`, which is not a registered code, and a duplicate of the informational `signingCredential.ocsp.skipped` in the failure bucket. When stapled OCSP responses disagree, a qualifying `good` response now settles the status, and the outranked `revoked` one is reported as `com.encypher.ocsp.conflictingRevokedResponse`. The default posture still treats any `revoked` response as decisive.
- CAWG identity validation follows the Identity 1.3 data model: nested identity references and reference cycles are rejected, the identity time-stamp is resolved before the manifest time-stamp is used, all seven C2PA COSE algorithms are accepted for identity claims aggregation, `did:web` documents are followed through `assertionMethod` and `controller`, and the full `signer_payload` is compared with `credentialSubject.c2paAsset`.
- X.509 identity signatures (`cawg.x509.cose`) report the registered CAWG Identity 1.3 status codes in place of the Encypher-scoped ones. Integrators mapping codes should rename `com.encypher.cawg.x509.signatureMismatch` to `cawg.x509.signature.mismatch`, `.algorithmUnsupported` to `cawg.x509.algorithm.unsupported`, `.credentialInvalid` to `cawg.x509.credential.untrusted`, `.credentialExpired` to `cawg.x509.signature.outside_validity`, `.ocsp.notRevoked` to `cawg.x509.ocsp.not_revoked`, `.ocsp.skipped` to `cawg.x509.ocsp.skipped`, and `com.encypher.cawg.identity.timeStamp.invalid` to the informational `cawg.x509.time_stamp.*` set. New codes are `cawg.x509.credential.trusted`, `cawg.x509.signature.validated`, `cawg.x509.signature.inside_validity`, `cawg.x509.time_stamp.trusted` and `.validated`, and `cawg.x509.time_of_signing.inside_validity` and `.outside_validity`.
- An identity credential that reaches none of the configured CAWG trust anchors is now the failure `cawg.x509.credential.untrusted` instead of the `cawg.identity.well-formed` success. With no CAWG trust material configured there is no root of trust to reach, and the assertion still reports `cawg.identity.well-formed`. CAWG results stay assertion-scoped and never change `integrity` or `validation_state`.
- The identity time-stamp follows the 1.3 source order: the assertion's own `sigTst2` header, then the `c2pa.time-stamp` assertions recorded for the containing manifest, then the claim signature's time-stamp. A v1 `sigTst` token or any other unusable time-stamp is now informational and ignored rather than a failure.
- An identity credential that can only be validated by fetching material over the network reports the registered failure `cawg.identity.network_traffic_blocked`. A `did:web` issuer with no pinned DID-document store is the current case; a store that does not carry the DID still reports `cawg.ica.did_unavailable`.
- The Content Credentials JSON (`content_credentials`) emitted under `strict_conformance` now follows the C2PA 2.4 crJSON specification and validates against its schema. Manifests are listed in reverse store order, so a conformance rubric finds the active manifest at `manifests[0]`; the claim is keyed after its JUMBF claim box (`claim` for v1, `claim.v2` for v2) and keeps the generator-info shape that generation defines; every manifest carries a `signature` object with the signing certificate and any timestamp, alongside a `validationResults` object with `validationTime` and `specVersion`; CBOR byte strings render in the `b64'...'` form. Default-posture reports are unchanged and still emit no crJSON.
- Strict mode reports `signingCredential.untrusted` when no claim-signing anchors or allowed certificates are configured, instead of emitting no trust status. The default posture still reports trust as `not_evaluated`.
- The packaged trust snapshot is refreshed to 2026-09-24. The C2PA Trust List and C2PA TSA Trust List each gain the Castlabs C2PA ECC P-384 Root CA (added upstream on 2026-08-13); no anchor was removed. The other sources are unchanged.
- An update manifest's inherited data hash is checked against the store as it stands now: the store exclusion takes the store's current length and later exclusions shift by the difference, as C2PA 2.4 requires.
- A collection hash inherits the claim `alg` when it has none, and reports `algorithm.unsupported` rather than a malformed or mismatched hash for a missing or forbidden algorithm. Unlisted files in a collection are allowed; listed files must all be present.
- Strict mode reports `com.encypher.conformance.outOfScope` and `com.encypher.conformance.specVersionNonConformant` in place of the unregistered `conformanceScope.*` codes, checks carrier placement for GIF, TIFF, SVG, and BMFF, and writes `algorithm: "Unknown"` in crJSON for a readable but unsupported signature algorithm.
- A v1 claim that carries `claim_generator` but no `claim_generator_info` is informational `com.encypher.claim.generatorInfoMissing` by default and `claim.malformed` under strict conformance, and default verification continues through the signature and hard-binding checks. A legacy `c2pa_manifest` ingredient link hashed the C2PA 1.0 way, over the ingredient's claim bytes, is accepted by default as `com.encypher.ingredient.legacyClaimHash`.
- JPEG box hashes follow C2PA 2.4 restart segmentation (each `RST[n]` owns the entropy data after it). The default posture also accepts the overlapping layout c2pa-rs writes, which still hashes every byte, as `com.encypher.assertion.boxesHash.overlappingRestartSegments`; strict conformance does not.
- A CAWG identity may reference an assertion in any ingredient claim reached by recursive validation, and an identity inside an update manifest resolves its hard binding through the parentOf chain.
- `cawg_strict_encoding` (`--cawg-strict-encoding`, Python `cawg_strict_encoding`, Go `CAWGStrictEncoding`) now refuses the CAWG field-order `signer_payload` that c2pa-rs writes, the one legacy encoding the default posture still accepts (with `com.encypher.cawg.legacyProfile`). The CAWG 1.1 ICA context and byte-array `c2paAsset` hashes it also refused are rejected in every posture under CAWG Identity 1.3. `strict_conformance` refuses the field order either way.
- Every supported format can be named by its file extension. Files ending `.oxps`, `.xps`, `.ods`, `.odp`, the Office template and macro-enabled variants, Visio files, `.heics`, `.heifs`, `.sfnt`, `.csv`, `.md`, `.html`, `.xhtml`, `.xml`, `.css`, `.js`, `.json`, `.yaml`, `.toml`, and `.py` previously failed on path-based verification as an unsupported MIME type unless the type was passed by hand.
- Under strict conformance, a v3 ingredient that links a manifest without recorded `validationResults` is `assertion.ingredient.malformed`, and an external reference in `created_assertions` is `assertion.external-reference.created`.

### Removed

- The CAWG test chain's private keys no longer ship in the crate; tests mint their signing chain at runtime.
- Validation of the `expected_partial_claim`, `expected_claim_generator`, and `expected_countersigners` fields, which CAWG Identity 1.3 deletes from the `signer_payload` schema. A validator must not consider undocumented fields, so a payload that still carries them is accepted and the fields are ignored. The codes `cawg.identity.expected_partial_claim.mismatch`, `cawg.identity.expected_claim_generator.mismatch`, `cawg.identity.unexpected_countersigner`, `cawg.identity.expected_countersigner.mismatch`, and `cawg.identity.expected_countersigner.missing` are no longer reported.

## 1.0.6 - 2026-08-31 (not published)

Prepared but never released to a registry. These changes ship in 1.1.0.

- ZIP collection verification now builds one bounded central-directory index and performs constant-time member lookup, removing a quadratic high-entry archive denial-of-service path while preserving duplicate, ZIP64, traversal, member-set, and hash checks.
- Collection verification now decodes canonical RFC 3986 member URIs before ZIP lookup and compares the complete declared and presented member sets. DOCX members such as `%5BContent_Types%5D.xml` verify against their raw archive names, while lowercase escapes, over-encoded unreserved bytes, traversal, schemes, queries, fragments, and alternate separators still fail closed.
- Fixed a `claim.malformed` regression that rejected any manifest carrying a claim-generator icon. A `claim_generator_info` icon is a hashed-URI pointer to an assertion the claim also declares, not a second declaration of it, and claim v1 lets several generator-info entries share one icon. Icon references were being merged into the same set used to detect a label declared twice, so a conforming manifest, such as those written by OpenAI's image service, failed with `claim declares assertion 'c2pa.icon' more than once`. Icon references are still resolved and hash-verified individually; declaring one assertion twice in `assertions`, `created_assertions`, or `gathered_assertions` remains a fatal `claim.malformed`.

## 1.0.1 - 2026-08-11

## 1.0.0 - 2026-08-10

- Consolidated the six implementation crates (`encypher-c2pa-cbor`, `-core`, `-crypto`, `-formats`, `-trust`, `-validate`) into private modules of `encypher-c2pa`. They had no consumer, accounted for 81% of the public API surface, and publishing them is what forced manifest construction to hide behind a Cargo feature. All releases through `1.0.0-rc.11` of the facade, CLI, and six implementation crates are yanked; existing lockfiles continue to resolve, while fresh resolution waits for the stable release. New releases publish only `encypher-c2pa` and `encypher-c2pa-cli`.
- Removed manifest construction and container writing from the published API. Claim building, JUMBF and manifest-store assembly, `embed_manifest`, `strip_manifest`, and `build_manifest_carrier` now live in private modules and compile only under `cfg(test)`. The SDK reads and verifies C2PA manifests and exposes no way to produce one. The `test-support` feature introduced for this purpose is gone; module privacy replaces it.
- Breaking change for anyone depending on the six implementation crates directly. There are no known consumers. Use `encypher-c2pa`.
- Added `scripts/check-public-surface.mjs`, a CI gate that enumerates every publicly reachable item and diffs it against the reviewed `public-surface.txt`. Any newly public item fails the build until a reviewer adds it deliberately, so a renamed writer cannot slip through the way a name-based check would. The gate runs on every pull request and before every release.
- Added pinned, offline c2pa-rs core and CAWG interoperability corpora with fixed source commits, checksums, normative expected status codes, and CI enforcement.
- Fixed legacy ES256 verification, claim-v1 RFC 3161 timestamp handling, manifest-carrier exclusion normalization, and ingredient active-manifest and claim-signature authentication.
- Completed BMFF hard-binding verification across the full nested box tree: `c2pa.hash.bmff` V2 and V3 exclusion maps now resolve container boxes at any depth, apply each map's `data` match conditions and `subset` byte ranges, and read full-box version and flags, under bounded tree depth and box counts.
- Enforced the mandatory C2PA 2.x actions structure on standard manifests: a created actions assertion must be present, its first action must be `c2pa.created` or `c2pa.opened` (a `c2pa.created` action requires a `digitalSourceType`), and exactly one such inception action may appear and only in first position; otherwise verification reports `assertion.action.malformed`.
- Hardened untrusted-input verification: claim-v1 timestamps no longer anchor signer-certificate validity, positive stapled OCSP status now requires a trusted signing timestamp and the C2PA `producedAt` freshness window, ambiguous or oversized JUMBF labels fail closed, manifest stores are capped at 64 MiB, assertion and reference collections are bounded and indexed, and BMFF exclusion and Merkle chunk processing use bounded work and checked arithmetic.
- Completed C2PA 2.4 assertion integrity checks: undeclared assertions fail closed, canonical JUMBF paths and cardinalities are enforced, one primary hard binding is separated from the `c2pa.hash.multi-asset` fallback, and the operative binding is carried into CAWG identity validation.
- Added full bounded multi-asset validation for byte-range and BMFF-box locators with part-specific data, BMFF, and general-box hash methods. Ingredient, assertion, CBOR, JUMBF, JPEG APP11, BMFF Merkle, x5chain, CAWG identity, and embedded OCSP processing now have aggregate work, allocation, count, and byte limits.
- Made embedded revocation evaluation store-wide and order-independent, with verified revocation taking precedence over good status, exact BasicOCSPResponse typing, bounded responder selection, and the C2PA embedded-evidence timing policy.
- Removed the `cawg_document_signing_require_anchor` option and CLI flag. CAWG document-signing credentials now always require a caller-supplied CAWG trust anchor or allowed-certificate match.
